# consumption-notes.md — 原优化版（V4.1e）接口消费清单

范围：`初代热血硬派优化版.sfc`（固定 SHA-256 `2008f9…fe08`，1.5MB）。
本文只列**接口、索引来源、必须保留的行为**，以及供重新汉化时挂接的位置；所有结论都有
`check_native_contracts.py` 的字节级锁定（见 `contracts.json` / `results.json`）。

**总原则**：字节串只有在"已确认的代码块内、且经线性反汇编对齐验证"时才是指令。
数据区（bank $20 的查表区、bank $23 文本、`$00:FFC0` 片尾文本、`$00:B500` 表等）里的
`22`/`5C`/`DC` 一律只是数据字节——即便它们恰好能译成 JSL/JML/JML[ind]，也不得当作可执行入口。
本次 52 个候选里就有 5 个这样的"数据里长得像指令"的假阳性，已全部剔除并锁定了区域哈希。
两个容易误判的具体字节（只有落在已验证代码块内才成立）：
- `7A` = **PLY**：bank $20 stub 的收尾序列 `7A AB 5C …`（PLY; PLB; JML 回原 bank）
  是真指令（已对齐验证）；但同样的 `7A` 出现在字库/文本数据里只是数据值。
- `9E` = **STZ absX**：作为指令名如此；而在 FA/FB 字形表里 `9E` 是"浊点叠加"的
  表值常量，与代码无关。

---

## 1. 文本管线（原优化的 loader / stream 扩展）

原版（JP）的消息指针建立例程在 `$03:EB68` 起。优化版把它改成两处跳板：

| 站点 | 补丁 | 作用 |
|---|---|---|
| `$03:EB70` | `AD 4A 03 0A` → `5C 00 80 22`（JML `$22:8000`） | 消息指针建立（loader） |
| `$03:EBBB` | `B1 20 85 12` → `5C 50 80 22`（JML `$22:8050`） | 流取字节（stream fetch） |

**$22:8000 loader 合同**（字节锁定 `$22:8000–$806C`）：
- 宽度：索引 = 16 位，拆成 `$034A`（低）+ `$034B`（高）；表项 16 位小端。
- 分派：`$034B < 3`（即索引 < `$300`）→ 原路：`A = $034A<<1` 后 JML 回 `$03:EB74`
  （继续原始"index*2 + 基址 `$EAEB/$EAEC`"逻辑）。`$034B >= 3` → 扩展路：
  `$034B -= 3`，指针 = 读 `$22:8070 + 2*(index-$300)`（小端 u16）→ 写入 `$036A`(低)/`$036B`(高)。
- DBR：读表期间置 `$22`（`PHB/LDA #$22/PHA/PLB`）；返回前 `PLB` 恢复调用者 DBR。
- DP：直接用调用者的直接页：scratch `$20/$21`、结果 `$12`——与原始 loader 路径同一
  套 DP 变量，扩展代码从不重载 D。
- 返回：`CLC` + RTS（经 `$03:EB9A`）；索引==0（`$034A|$034B==0`）时 `$03:EB68`
  分支到 `$03:EB9C` 的 `SEC`+RTS。

**$22:8050 stream 合同**（字节锁定）：
- 入：`$20/$21` = 当前读指针（调用方从 `$036A/$036B` 复制），Y = 偏移，`$034B` 决定来源。
- `$034B < 3` → 用调用者 DBR 读；`>= 3` → 置 DBR `$23` 读（`PHB/LDA #$23/PHA/PLB` … `PLB`）。
- 出：A = 字节、dp `$12` = 字节，然后 JML `$03:EBBF` 继续原始分派
  （`CMP #$F3` 行尾 / `>=F0`、`<E0` 走 `$03:EBD0`，`E0–EF` 走宏展开 `$03:EBFC`）。
- 文本码宽度 = **1 字节**（A/$12）；扩展只换字节来源，不动控制语义。

**扩展表（bank 指针表）**：`$22:8070`，76 项 × u16 LE。
- 项 0（消息 `$300`）= `$0000` 空/边界槽；项 1..75（消息 `$301..$34B`）= `$8000 + (文件偏移-0x118000)`，
  严格递增，末项 `$871D`。已与 `optimization-new-text.json` 75 条逐条互核通过。
- 每条消息首字节 ∈ {`E2`,`F0`,`F3`}；文本区 = bank $23 `$8000–$8740`（`$873F`=`F3`，其后全零）。
- 资源占用：bank $21 全空、bank $22 `$8108` 之后全零、bank $23 `$8740` 之后全零、bank $24+ 全空
  ——新字库/新接口的可用空间在这些区域。

每次消息读取都经同一"索引拆两半 + `$300` 阈值"的判定，所以**新增消息**必须按
`index = $300 + n` 的同一编号体系走 `$22:8070`/bank $23（或整体搬迁但保留这两处入口合同）。

## 2. 姓名（514 条人物姓名记录）

- 表头：`$09:8000` = 表基址 u16（=`$802A`）、`$09:8002` = 表尾 u16（=`$A04A`）。
  记录区 = `$09:802A..$A049`，**514 条 × 16 字节**。
- 记录结构：前 **4 字节 = 姓名文本**（假名码，`00` 填充，最多 4 码；CN 旧方案写 2 汉字=4 字节）；
  第 4..15 字节 = **参数区（非文本）**，任何文本消费者都不读。
- 参数非文本的证据（代码级）：姓名宏展开 `$03:EC95`/`$03:ECB5` 都用 `CPY #$04` 封顶
  只拷前 4 字节（字节锁定 `C0 04 B0 13` / `C0 04 B0 11`）；且 `$09:8004` 起还有一张
  **19 项参数指针表**（`$A224,$A9A4,$A9C0,$AA56,…,$B85E`，严格递增，全部 > 表尾），
  指向记录区之外的参数块——表尾 `$A04A` 起即参数数据。
- 索引来源（native 入口）：
  - `E0` → 固定索引 `0x200`（记录 512 = くにお）；`E1` → `0x201`（记录 513 = りき）；
  - `E2`（每句开头的说话者）→ 读 **`$034C/$034D`（u16）**；
  - 记录地址 = **`index*16 + u16($09:8000)`，bank `$09`**（`$03:EC7F..EC94` 的
    `ADC $098000/$098001` + `LDX #$09`，字节锁定）。
- 宏分派表 `$03:EC0D`（E0–EF 共 16 个 u16 入口，字节锁定，优化版**未改动**）：
  `E0→EC2D, E1→EC3C, E2→EC4C, E3→ECD3, E4→ECD7, E5→ECDB, E6→ECDF, E7→ECEB,
   E8→ECEF, E9→ECF3, EA→ED43, EB→EDAE, EC→EDC5, ED→EE05, EE→EE0A, EF→EE21`。
  `ED/EE` 走 2 字节表（基址 `$EAF3/$EAF4`，索引 `$035D/$035E`）；`EF` 用指针 `$035F/$0360`。
- 姓名渲染仍走 FA/FB 单字节码（`FA=$01FA9E` 基形、`FB=$01FB9E` 浊点叠加；两表与 JP 一致）。
  重新汉化改字库时：姓名码仍必须是"FA/FB 能画出"的单字节码，或同步改
  `$03:EC95/ECB5` 的拷贝宽度——两边必须一致，否则说话者名字会散架。

## 3. 菜单（六命令暂停菜单 + 坐标）

优化版把原来的 5 项暂停菜单改成 **3 列 × 2 行 = 6 项**，新增项为「どうしうち」（同士討ち）。

| 接口 | 地址 | 说明 |
|---|---|---|
| 入口/分派 | `$00:F580` → JML `$20:9020` | 按 `$0368` 六路分派（`#$05` 为第 6 项），`$0368==4` 走新处理 `$20:9058` |
| 标签表读取 | `$03:F841` → JML `$20:9000` | `Y=$039A`；`$F845,Y→$039F`（行）、`$F84B,Y→$03A0`（列） |
| 光标自增 | `$03:F811` → JML `$20:9013` | 三重 `INC $039A` 后回 `$03:F817` |
| 输入钩子 | `$03:F7AE` → JSL `$20:9170` | 隐藏输入（按住 L+R+X 时的附加位掩码），返回 A 的 bit7 控制分支 |
| 标签布局 blob | `$03:F743`（52 字节 = 2 行 × 26 格） | `$20:9090` 拷到 `$040A`；绘制方 `$03:F95D` 逐格用 FB 上 tile / FA 下 tile |
| 光标绘制 | `$03:F8BD` | 读 `$039F`（行，`$03:F8CA`）与 `$03A0`（列，`$03:F8E5`）→ 画光标格 |
| 计数常量 | `$03:F7EB` `C9 05`、`$03:F80D` `C9 03`、`$03:F81F` `CPY #$03` | 6 项边界（原版是 5/2/2） |

**六命令表与坐标（字节锁定 `$03:F845`/`$F84B`，各 6 字节）**：

| item | row (`$F845`) | col (`$F84B`) | 标签（blob 解码） |
|---|---|---|---|
| 0 | 0 | 0 | きりょくをつかう |
| 1 | 0 | 10 | アイテムをつかう |
| 2 | 0 | 20 | そうびする |
| 3 | 1 | 0 | ステータスをみる |
| 4 | **1** | **10** | **どうしうち（优化版新增）** |
| 5 | 1 | 20 | すてる |

- 处理函数映射（`$00:F59D/$F5A3/$F5A9/$F5AF/$F5B5` + 新 `$20:9058`）必须保持：
  0→F59D, 1→F5A3, 2→F5A9, 3→F5AF, 5→F5B5（原第 5 项），4→`$20:9058`（新项，
  读 `$0E21/$0E22`、翻转 `$70` bit7、`JSL $07:D872` with `#$2C/#$2F`，并经 `$20:9090`
  往 `$0435/$0436` 写两组码 `$34/$2B` 或 `$20/$47`——用途未确认）。
- 旧 5 项坐标表被移到 `$F845/$F84B` 原址处（`$03:F851..$F85A` 已 NOP 填充，字节锁定）。
- **重新汉化菜单标签的接口**：只需改 `$03:F743` 的 52 字节 blob（码必须是 FA/FB 可画的
  单字节码、且不与正文控制码冲突），坐标表 `$F845/$F84B` 与 `$039A/$039F/$03A0` 体系不要动。
  blob 的 6 段标签位置已解码列出（上方表），格子坐标 = 光标 (row,col) 的 col+1 起。

## 4. 必须保留的原优化行为（回归清单）

1. 两处 loader/stream 跳板及其完整寄存器合同（§1）；特别是 `$034B<3` 的原路回跳。
2. `$300` 阈值与 `$22:8070` 76 项表（含 `$300` 空槽、`$301` 首条）；bank $23 文本区
   边界 `$8000–$8740` 与其后的零填充。
3. `$09:8000` 表头双字（基址/尾）+ 514×16 记录布局；姓名 = 4 字节；参数区不被当文本。
4. E0–EF 宏分派表原样；E0/E1 固定索引 `0x200/0x201`；E2 走 `$034C/$034D`。
5. 六项菜单：`$20:9020` 六路分派（`CMP #$05`）、三处计数常量、`$03:F845/$F84B` 坐标、
   `$20:9000/$9013/$9090`、`$03:F8BD/$F95D`、`$20:9170` 隐藏输入、菜单关闭流
   `$03:F85B` 与 `$20:9013` 的三重 INC。
6. 全部 **47 个原银行 → bank $20/$22 的 JSL/JML 入口**（`contracts.json.entry_sites`：
   站点、目标、对齐证据、stub 返回目标 sweep）——这些是优化版的修正逻辑，
   新构建不得覆盖 bank $20/$22/$23 而不重新实现它们。
7. 资源块摘要（`contracts.json.bank_blocks`）：三个 bank 的块跨度 + 逐块 sha1 + 整 bank sha1
   + 块外零填充。

## 5. 建议的新实现 hook 点（只给接口，不替主代理设计）

- **文本**：唯一会聚点是 `$22:8000` / `$22:8050` 两个入口；新字库/新编码最安全是
  保持这两个合同不变、只替换其背后的表/文本（bank $23 或新 bank）。
  若必须改为多字节码，改 stream 合同会连锁影响 `$03:EBC1` 分派与 F2/F3 语义——不建议。
- **姓名**：保持 16 字节步长与 4 字节名字段；新码体系沿用"记录索引×16 + 表头基址"，
  并同步 E0/E1/E2 三个宏处理器的拷贝宽度。
- **菜单**：只改 `$03:F743` blob；坐标与分派保持。若改菜单文字长度，
  需保持每格 1 字节码并在 26 格/行内排布（超格会串到 `$040A` 之外）。
- **可用空间**：bank $21（全空）、bank $22 ≥ `$8108`、bank $23 ≥ `$8740`、bank $24–$2F 全空。

## 6. 未确认合同（explicit unresolved）

见 `contracts.json.unconfirmed` 与 `results.json`，摘要：
- 47 个入口 stub 的**运行时语义**未验证（只做了字节/边界/返回目标级验证，未跑模拟器）。
- `$20:9058` 新菜单项语义、`$0435/$0436` 两组码用途、`$20:9170` 隐藏输入的完整效果。
- bank $20 `$8000–$814D` 逐人查表（`$0F01,X`→`$0E11,X`）字段含义、`$09:8004` 19 个参数块内容。
- 5 个被剔除的 `DC` 假阳性中 3 个（`$00:B51A/$B51F`、`$04:C0DA`）在数据区"巧合对齐"，
  分类依据是区域证据而非控制流。

## 7. 复核方式

```
python contracts-worker/check_native_contracts.py
```
读固定优化 ROM（SHA 锁定），输出 `contracts.json`（全部合同与验证状态）与
`results.json`（基线 0 违规 + 12 项负例全部被拒的证据：改签名/改表边界/改指针/改入口
/改 loader 补丁/复活 bank23 尾巴等）。
