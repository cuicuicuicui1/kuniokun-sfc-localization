本记录补充 rc6，不取代 [现行版本身份](current-state.md)。根目录冻结产物仍是 rc4；本地 rc6 CRC32 是 `DCEB2D50`。截图、即时存档、内存与商业 ROM 仅留在隔离本地证据目录，不加入 Git。

## 1. 用户指出的实际场景

用户给出了地下停车场三名混混、聪的战后奖励，以及浦部说“警察来了，快进去”的日版视频截图；汉化现场是三名混混已打倒，右边门仍关闭、主线无法进入。

定位到原地图 `$4B`、原 event `$15`（运行时 `$95`）。这里的**第一扇右门通向地图 `$4C`**；后续 event `$17`（运行时 `$97`）还等待下水道 `$5A`。进入 `$4C` 不等于已到下水道或已完成整段主线。

## 3. 原消费者与条件

以下只适用于本项目核对过的 LoROM，**不要推广为其他 SFC 游戏的地址表**。

- `$04:B61E`：event15入口；原 VM 安装，不编辑脚本PC。
- `$04:B94B`：最终三人战斗等待点。`$122B/$122D` 是战斗阶段；不能简单把活跃标志清零就宣称完整 KO/奖励流程通过。
- `$04:B9A1 / B9A9`：原消息0153 / 0154，即警方到来、赶快进门。
- `$04:B9D4 / B9D6`：原 opcode63移除对象95、opcode62登记对象94。当前对象列表在 `$08C6..08D5`。
- `$02:F4C2`：原门处理。战斗仍进行时会早退，所以看到新敌人或关门图片，不能直接判为文字钩子破坏剧情。
- `$02:F9A2`：读取门的 blocker `$0455`，检查完整对象列表。右门的 blocker 为95。
- `$02:F737`：原地面坐标、方向、角色状态判定。仅在门附近按键，也可能不在有效范围。
- `$02:F8CB`：原入口动作被接受；探针必须命中它，并随后真正进入 `$4C`，才算这扇门的输入重放通过。
- `$02:F413`：原换图条件，包括另一玩家准备情况。普通双人不提供P2输入会造成等待，不等同于CPU同伴。

探针使用**物理PRG-ROM回调地址**，避免CPU bank别名使监测零命中。所有具名通过还记录ROM CRC/SHA、源状态身份、消费者命中次数和换图结果。

## 4. 本轮新增工程文件

- [输入重放探针](../hw/mesen_garage_probe.lua)：不写 WRAM/SRAM/ROM，不改CPU或脚本PC；可关闭自动对话/进门，仅采集现场。
- [显式受控准备](../hw/mesen_garage_jump.lua)：通过原加载器/VM准备事件；早期分支与战斗有捷径，最终战斗用低起始HP + 原攻击/KO/奖励。设有准备结束后的写入断言。
- [分阶段运行入口](../tools/run_garage_story.py)：默认只重放；`--prepare` 才跳剧情；同ROM侧车与原消费者字节必须匹配，输出目录必须为新目录。
- [无ROM安全单测](../tests/test_garage_runner.py)：11项通过；只验证输入保护和探针合同，不验证游戏。

入口的 `--expect advance` 要求“原门动作接受 + 实际进入4C”；默认 `--expect capture` 只表示采集完成，不计开门通过。失败同样保留 manifest、runner日志和Lua日志。准备采用“最多10000帧、到警方检查点即停止”的上限，manifest另记真实执行帧数，不虚报跑满；原主循环保存边界允许最多2帧宽限，仍保留实际帧数。ROM临时名含CRC和输出路径摘要，避免不同运行复用同一个自动SRAM名字。
