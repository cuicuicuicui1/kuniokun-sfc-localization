# 初代热血硬派汉化 v39-rc2：实玩修复记录

**候选版，不是完整汉化或通关验收版。** 本轮按用户要求，已用无头 Mesen 从文件选择进入实际游戏，而不再仅凭开场动画截图判断。

## 版本与使用

- 干净原版：1,048,576 字节、CRC32 `56C05339`，不能带 512 字节附加文件头。
- 上一候选版 v39-rc1：CRC32 `990A69F4`。
- 本轮 v39-rc2：2,097,152 字节、CRC32 **`DADB84AB`**。
- ROM SHA-256：`399aade5a766d6b7703df9b2582c31cf2ca1f94ef3289620883089bd3fdc4153`。
- IPS SHA-256：`727fc6d224c6dbf81a49cc0e7802441eaf653dc033244a4b6c2539d189ca80c6`。

IPS 应用于干净原版，**不要叠加到 v38/v39-rc1 汉化 ROM**。本次字形池重新分配，复测应冷启动；旧即时存档可能保留旧文本编码和 VRAM，不能用它验收新版本。普通 SRAM 存档和即时存档不是一回事；先保留个人存档副本。

发布包只包含 IPS、源码修改、日志、JSON 证据和截图，不含 ROM、SRAM 或即时存档。F 盘模拟器中的旧 ROM、网盘旧发布物、玩家存档均未替换。原版文件保持只读；未停止用户已有模拟器，未改 snes9x 快进配置，未提交或推送 Git。

## 1. 这轮修了什么

### 1.1 刚出现的台词被误擦，导致“太快、来不及读”

旧 STALEROW 按 `$036E - $0391 == 1` 和列号判断“残留行”。正常的 F2 换行后，下一行补空同样满足条件，结果把刚写完的文字擦掉。

默认关闭这个不安全的额外擦行钩子。正常行首清理、显式清屏、菜单关闭清理仍然保留，原版闲置计时器 240 不变。新的回归直接运行真实消息 tick 和绘制器，检查第 0、4、14、15 行在换行补空后仍保留文字；对旧版运行会明确失败，不再用测试“成功擦掉文本”证明它正确。

该缺陷最早在开场复现；这轮进一步检查了实际旅馆提示、空道具提示及战斗 NPC 台词。尚不把局部覆盖等同于所有剧情都正确。

### 1.2 按住/松开的出字节奏

`$0316/$0318` 是新按下的边沿状态，`$031A/$031C` 才是 P1 持续按住状态。旧代码读取错误地址，还把 X/Y 的位也当成 A/B。

现在读取正确的 held 字节，仅用 bit7 判断 A/B；快进和缓冲耗尽时清空旧倒计数，松开后不继承残余等待。默认 PACE=6 保持不变，它是**消息 tick**，不是固定 6 个视频帧。

实际同一 NPC 台词中，普通绘制尝试出现在第 4、16、28、40、52 帧；持续按住 A 时连续尝试集中在第 2、4、6 帧。中途松开的另一次实测，在释放后恢复第 4、16、28 帧的间隔。日志中的 DRAW 是绘制尝试，队列忙时可能重试，不能当作每一条都已在屏幕显示一个新字。

游戏文件菜单的确认键实测为 **Y**，不是之前测试中反复按的 A；新测试逐项核对实际手柄状态，防止“脚本按了，但游戏没收到”的假通过。

### 1.3 实际游戏 Start 菜单破坏生命条

冷启动进入旅馆，先移动，再打开 Start，旧字形分配会把血条瓦片 E7..EF 当作中文池空间；抓取的 VRAM 中 E8..EF 已变成汉字片段。

修复分两部分：

1. 将血条 E7..EF 和边框 F2 列为不可分配图形。
2. 原版敌我两组九级血条位图逐字节相同，让敌方也引用同一组图形，保留原来的调色板选择。仅改两个立即数，不增加每帧 DMA 或队列负担。

同时，不再替已经由专用渲染器汉化的状态标签保留废弃假名字形；仍在使用的角色名和状态词原始瓦片则显式保留。新配置正文槽位 **37**（原来 36），共 **26** 页，列表共存窗口仍为 **9**，未通过削弱旧共存范围来挤预算。新增构建边界检查，拒绝字形池覆盖补丁代码银行或道具前缀。

Mesen 冷启动重新走同一条路线，菜单、状态返回、大厅和战斗七个抓取点的十个血条图形全部与原版字节一致。战斗中生命值实际下降，红/蓝生命条正常显示。

### 1.4 文本小范围校订和测试补强

对照原日文校订 9 条文本，保持各条现有控制标记顺序不变，例如：

- “算” → “算了”。
- “理由由我来说” → “让我说明原因”。
- “一个有来往的女孩” → “一位女笔友”。
- 修正把对大阪联合总长的无礼称呼误译成“抓住总长”的句子。
- 删掉被错误重复三次的停顿横线，保留原有停顿控制码。

详细前后文保存在文本校订 JSON。状态/装备模型不再吞掉未知指令异常作为“成功返回”；槽表长度改为读取构建元数据。

## 2. 实际操作覆盖，而非只看动画

主路线：**15,120 帧冷启动 + 同版本检查点续跑 7,240 帧**。没有用改游戏 RAM、瞬移或伪造战斗标志进入这些场景；唯一初始化数据为玩家 SRAM 的只读副本，随后通过手柄操作。

1. Start 进入文件选择，Y 确认，命名并完成新游戏。
2. 推进新游戏站台/旅馆剧情，进入可控制角色的房间。
3. 实际向右、向下移动，Start 打开菜单。
4. 打开状态页，B 退出；离开房间到走廊。
5. 行走至电梯，选择一楼，进入大厅。
6. 与大厅 NPC 发生战斗，移动、攻击，观察受伤和敌人台词。
7. 从该版本自己的检查点分支测试：不按键阅读、按住 A、台词中途松开 A。
8. 另测道具和装备入口，当前测试角色背包为空，显示“道具没有带”。**这只覆盖空列表提示，不声称测试了有物品列表、使用或更换装备。**

完整主路线之后的分支另跑 2,400 帧。本轮当前候选版自然流程总计 **24,760 帧**。六个定向 HUD CPU/队列测试另算；它们使用仪器化临时副本，不冒充自然战斗验收。

## 3. 验证结果

- 17 项自动检查 PASS，另 1 项瓦片占用 INFO；没有把 INFO 当作安全性证明。
- 三个负例：旧 v39-rc1 分别因误擦新文本、held 按键无效、字形池占用血条而被新测试拒绝。
- 连续两次构建：ROM、IPS、三份元数据 SHA-256 相同。
- 全套校验前后构建产物哈希不变；IPS 从干净原版重放与当前 ROM 完全相同。
- Mesen 六项完整 HUD 例程测试全通过（含双字、单字、跨页、队列繁忙、假名）。
- 当前候选版自然冷启动、菜单与战斗截图、按键轨迹、VRAM 字节核对均有落盘证据。

## 4. 未完成和下一步

- **存档/命名界面仍有日文**；这些是独立压缩 tilemap，不能按普通对白字符串替换。
- **状态页 8×16 中文过窄、拥挤，可读性差**。本轮实测的字形上传与表项一致，不是这张图的随机指针错误；后续应重做字号/列宽排版，而不是只换译文。
- 状态页“ふつう”等状态词和实际角色 HUD 的原名仍未完全汉化。
- 32 条译文仍含假名，主要涉及制作人员姓名，不臆造其汉字姓名。
- 长剧情跨消息共存、商店、有物品菜单、道具使用与 HUD 名字槽共存仍需扩展实测；更不能承诺“卡住全部消失”。
- 尚未完成全流程通关和最后的双核心模拟器验收。
