## 已确认的根因（局部）

原引擎的文本队列是 **字节游标协议**：

| 地址 | 原引擎消费者 / 用途 |
| --- | --- |
| `$09DD` | 8 位文本队列读游标；NMI 消费后推进 |
| `$09DF` | 8 位文本队列追加游标 |
| `$09DE` | 另一条图形队列状态，不是读游标的高字节 |
| `$09E0/$09E1` | 16 位带符号列车位移；原程序 `$00:FC75` 写入 |

真实分配器 `$00:9AB6` 在 M=8 下只比较/清除 DD 与 DF。rc4 部分道具消息、HUD 和动态列表代码却以 16 位读 DF、以 X16 写 DF，或在 E0 非零时一直等待。这会把正在运动的列车误判为繁忙文字队列，或者把列车位移当成索引高字节。

旧 `dialogue_model.flush` 同时清零 DD..E0，遮蔽了这个问题。rc4 文档/测试中把 `256/511` 当作“满队列高字节”的论证，**被本轮原消费者证据纠正**：它们不是合法字节游标；相邻 E0 属于列车。原 rc4 记录保留为历史，不继续沿用该推断。

## 改动

- `Asm.queue_load_x`：从 DF 单字节加载并零扩展，保留完整 A（含隐藏 B）、P 与 Y；不通过 SEP X8 截断字形源的 16 位 Y。
- `Asm.queue_store_x`：只提交 DF 单字节，绝不连写 E0。
- HUD、道具消息、正文/清行以及动态列表改用对应的字节协议；动态列表删除 E0 非零就等待的错误门禁。
- 容量检查在提交值 256 之前延期，避免字节游标回绕为零。
- 静态菜单本就明确使用 X8，保留其短 LDX/STX，不为它盲目膨胀代码。上传器仍为 236 字节；新增上传器/表/下一段资源不重叠断言。
- 模型 flush 不再清除 DE/E0/E1；模型即时回收与原 NMI 的 DD-only 推进明确区分。
- 新 `test_train_queue.py` 注册到 `verify_all.py`；HUD、列表、菜单和清行测试加入带非零相邻状态的断言。
- `hw/mesen_train_queue_fixture.lua` 提供独立 Mesen 真实消费者对照，脚本顶部明确其 WRAM 夹具范围。
