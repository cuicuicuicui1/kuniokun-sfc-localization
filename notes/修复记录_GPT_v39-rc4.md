## 本轮针对用户的四张截图

### 1. 战斗时 HUD 名字（不是对话说话人标签）

原调用者 `$00:8C34` 把 `$22` 写在下行、`$23` 写在上行；汉字池却是上半字先存，因此旧补丁把两半颠倒。现在只交换中文分支返回的上下字形，原版假名路径不动。

敌方两块名牌原来与消息插入的人名/道具名共用字形槽，同一名牌第二字和另一名牌也会覆盖。现在保留独立的 8 个瓦片对（4 个 16×16 字形），私有表 ROM `$1F0780`。外层 `$00:8A96` 原只预留 82 字节，现通过原分配器预留 226 字节；繁忙时保留 dirty 标志，下一帧重试，而不是将未上传的名字标记为完成。

无头 Mesen 从新游戏进入旅馆、走廊、电梯、大厅战斗；实战敌名「三惠」「胜敏」正确显示。实际 VRAM 转储逐字节、逐格验证上下半字。双敌牌同时更新/延期与消息并发另由完整外层 CPU 模型验证；**没有自然复现车库原截图，也未自然验收右侧敌牌**。

### 2. 气力列表的招式名

真实路径 `$03:81D8` → `$03:F913` → `$03:F95D`。此前汉化修改了 `$03:E096` 指针表/名称，却没有修改列表绘制器，它仍将每个编码字节当假名单字。

现在在 `$03:F95D` 接入汉字列表解码器，保留原建行器与菜单状态机。四项同屏、上下滚动、16 行环形位置、关闭/重新打开均测试。静态 Start 五项标签通过原调用点单独旁路，避免把它的单字节 `$DD/$DE` 误认为汉字前缀。

### 3. 道具取得/使用消息内名称

`$DE` 道具分支原被前面的 `$DF` 下界判断挡住，直接调用子分支的旧测试不能发现这一点。本轮从真正入口 `$03:FA30` 开始验证并修正分派顺序。

另外修正两个真实模拟器暴露的 CPU 宽度错误：
- 逐字复制位图时 M=8 却按字宽步进，遗漏位平面字节，残留队列内容变成乱码；改为真正的 16 位复制。
- X/Y=16 时，`TAY` 会连同隐藏累加器 B 一起传送。之前 VRAM 地址的高字节使取 id 的 Y 指向错误 WRAM；现在明确零扩展索引。

CPU 模型同步修正 M=8 仍保留隐藏 B 的语义，并增加脏队列、256 个 id、满队列高字节等负例。Mesen 与 Snes9x 的真实「票券使用了」消息和 VRAM 字节正确；**本轮自然路线没有取得非空背包，拾取消息本身没有原截图级的自然重现**。它与实测使用消息共用的 `$DE` 消费者已回归，不把这升级成全拾取流程验收。

### 4. 非空道具菜单

真实路径 `$03:84B9` / 装备 / 丢弃 → `$03:F913` → `$03:F95D`。道具名单独增加 ROM `$1FA000` 的 16×16 像素字库，菜单不再挤成难辨认的 8×16 字形；状态页和消息的既有窄字库仍保留。

按实际物理行奇偶分配两行独立字形，修复连续滚动时两行变成同一名称的生命周期错误。沿用 `$00:9AB6` 分配器回收 NMI 已消费的队列，修复非空列表填满队列后永久卡住。没有强制刷新 PPU 或跳过游戏场景。

## 验证结果与边界

- **20 PASS + 1 INFO**；INFO 为槽位占用报告，不是假装通过的功能测试。
- 原版日文 ROM + 交付 IPS 重放逐字节等于交付 ROM；ROM/IPS/全部侧车元数据确定性重建一致。
- 原 rc3 真入口 `$DE` 负例失败，证明本轮补上旧测试漏测的问题。
- 560 条 HUD 名字完整调用链；两敌牌外层 dirty/retry；全部 110 个道具 / 35 个短名称；反复滚动和行号环绕；原 HP 位图、调色板和底边 HDMA 倒计时隔离。
- Mesen 冻结 ROM 的自然冷启动/操作/战斗 **18,700 帧**；受控菜单/消息 **3,260 帧**。只有菜单夹具将隔离运行时等级设为 99、背包设为 id 28..35；按真实按键进入菜单，未改 PC、未跳场景、未写玩家存档。夹具不是自然获得物品的证据。
- Mesen 6 个真实 CPU/队列定向夹具通过（不是游戏通关）。
- Snes9x libretro 同 ROM 冷启动及非空菜单/消息复核；名称像素与 Mesen 一致。原引擎闪烁光标位于空白分隔格，比较时只排除该光标，不放宽文字像素判据。
- 冻结版沿用 PACE=6 和 `$03E7`；不回退到引起底边漂移的 `$03C4`。

## 构建 / 重放 / 仓库

构建前设置 `PYTHONUTF8=1`、`PYTHONHASHSEED=0`，从项目目录运行 `cnbuild5.py`，再运行 `verify_all.py`。原 ROM、扩展基线、系统字体、字体资源都是本地输入，不包含在源码包中。

`tools/replay_runtime_names.py` 按 `hw/regression_routes/runtime-names-rc4.json` 分段重放，检查同 ROM 检查点及只读 SRAM 指纹。只有显式传 `--include-menu-fixtures` 才使用非空菜单诊断夹具。长的单段 27k 帧尝试退出过且路线不同，**没有列为成功证据**。
