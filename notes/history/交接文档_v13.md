## 4. 已确认的技术事实（别再重新逆向）

**文字渲染链**
```
抽屉钩子 $03:FA30 -> JML $3E:8200（我们的抽屉）
槽位表：每槽 2 字节 = 两个独立瓦片对（左半 t/t+1、右半 u/u+1）；16x16 汉字占 4 瓦片
字形池：ROM 0x108000 起（bank $21），POOL_STRIDE=64；抽屉把字形上传到字库窗口的空闲瓦片对
上传队列：WRAM $0B00 页，游标 $09DD（已刷）/ $09DF（已追加）；刷写器 $008385；
         房间助手 $009AB6 **永远清 carry**，排空时会复位两个游标；队列页上限 $F9
条目格式：[VRAM 字地址 2][$2115 1][字节数 1][数据]
```

**行映射（实测）**：文字行 k → 地图行 **2k、2k+1**（k = `$036E`，一个文字行占 2 个地图行）。
验证：f2592 时 `$036E=05`，抽屉写的正是地图第 10/11 行。
- `$036F` = 列（0 起）；`$0391` = **当前消息的起始行**（随消息前进，见 `hw/seq1.log`）；
- `$0374` bit4 = 文本会话门；`$03:FCC8` = 绘制序列开始——**实测极罕见**（900 帧只触发 1 次），
  **不能**当"每条消息"的信号用；
- 对话框内容地图在 VRAM 字地址 `$7C00`（字节 `$F800`）。

**瓦片账（v13 现状）**
- `free_pairs()` = 84 对（`HUD_ORIG=0`）；`HUD_ORIG=1` 时只剩 **62 对**；
- 着色用 DSATUR，**需要 34 色 = 68 对**（全局属性：脚本页/列表页里同时可见的字形数）；
- 标签 + 名字 = 16 对；68 + 16 = **84，正好用满**；
- 结论：**任何额外的"保护瓦片"都必须先腾出等量对**（1 对 = 2 个瓦片）。

**横条（已解决，别再改回去）**：说话人标签的字模原先放在瓦片 460-510（VRAM `$DCC0-$DFFF`），
那片字节**同时被别的图层当图块表读**（字符基址 $C000 的图层，其地图区在字节 $4000-$5800 一带），
于是每画一次标签就把场景某一行变成"半截字形 + 绿底"。修复 = 标签搬回字库窗口 +
压缩 7 条最长对话（`cn_translation.json` 里 `01C248/01AF34/01A7B7/01C896/01AFBC/01A15E` 已改短）。

以此腾出约 22 对瓦片，然后用这些瓦片依次换回：

1. **Start 菜单的中文标签**（`CMDWIN=1`，需要 10 对）；
2. **选项窗瓦片 209 的保护**（`PROMPT_CLOBBERED = frozenset({209})`，需要 1 对）；
3. 若还有余量：状态脚本的片假名还原（15 对）。注意 `HUD_ORIG` 现在是**一个总开关**，
   建议改成按分组的保护列表（道具名 / 状态脚本 / 名字记录），便于分步腾瓦片。

**具体执行步骤**
1. 找到道具名文本：ROM `0x01DCA1-0x01E096`（`untranslated_codes()` 里的 "item window text"），

   现有 `cn_translation.json` 的 key 是 ROM 偏移、值用 `{XX}` 表示控制码——道具名照这个格式加入，
   构建器会自己编码；**控制码必须逐字节保持原样**。
2. 构建器改造：让 `untranslated_codes()` 不再保护道具名那批码；`HUD_ORIG` 拆成分组开关；
   打开 `CMDWIN=1`、设 `PROMPT_CLOBBERED={209}`，然后构建——着色必须过
   （若报 `no feasible colouring window`，说明腾出的对还不够，先只开其中一项）。
3. 验收（缺一不可）：
   - `check16` / `verify16` / `safe16` 全绿；`ipsverify.py` `identical: True`；
   - `hw/rep1.lua` 复现：**横条必须仍是 0 帧**（改了瓦片账必须重跑）；

## 7. v14 实验：残留行擦除（**已回退，勿直接启用**）

**目标**：上一条消息留在屏幕上的文字行，其格子指向的槽位已被新消息复用 → 显示成汉字碎片。

**做法**：stub `$3E:C400`，由抽屉在"消息首行（`$036E == $0391`）的第 1/2 格"用 `JSL` 调用，
把 `$0391-1`、`$0391-2` 两个文字行的 26 格写成 `$2C00`（每次 112 字节，与抽屉自身 88 字节合计
200 ≤ 250 字节队列页；若放在**行首格**会变成 200+112 超页 → 抽屉永远推迟，仿真已证实）。

**已验证**：`test_stalerow.py`（门控/地址/队列满刷新并复位游标）全过；`verify16.py` 全过。

**实机结果**：**整屏乱码**（用户截图）→ 已回退；`STALEROW` 默认 0。

**下次排查顺序（别跳步）**
1. `$0391` 的语义是否真是"当前消息起始行"——探针实测（单条消息内是否恒定、跨消息是否 +1）。
   若它不是，delta 门控会在错误的行触发，最坏擦到框外 28-31 行。
2. **最可疑**：stub 在队列满时调用引擎刷写器 `$008385`。抽屉运行在每帧文本状态机里（不是 VBlank），
   刷写器是给 VBlank 用的。下次改成"**没空间就跳过、在后续列重试**"（不调用刷写器）。
3. `$09DF` 高字节假设（stub 只读写低字节，假定恒为 `$0B`）。
4. 单行消息时 `$0391-2` 不会被擦（只擦到 `$0391-1`）——要覆盖就改成在后续列重试。

## 8. 坑与红线（别再重复踩）

1. **JML 钩子必须写满 5 字节**（`5C lo hi bk EA`）：只写 4 字节会让 ROM 变短、后面所有偏移错位。
2. **栈操作宽度**：`pha/pla` 在 16 位累加器下吃 2 字节。stub 进出栈必须显式 `sep #$20`（v14 就栽在这）。
3. `$009AB6` 永远清 carry，**不能**用 carry 判队列余量，要直接比较 `$09DF`。
4. 低 WRAM 几乎没有空闲字节；存标志位用队列页尾部 `$0BF9+`（`$0BFB` 已被菜单清理用）。
5. 别用 `$03:FCC8` 当"每条消息"的信号（实测 900 帧 1 次）。
6. 瓦片空间实测：6 个场景里 1024 个瓦片号有 858-961 个被地图引用，从不被引用且**成对**的瓦片**不存在**
   ——"把驻留字形搬到字库窗口外"这条路是死的（v8.1→v12 全部白改的根源）。
7. 改任何瓦片账（保护/池/标签）后，**必须重跑 `hw/rep1.lua` 复现**，横条 0 帧才算过。
8. 交付前：`PYTHONHASHSEED=0` 构建 + 四校验 + IPS 往返 + 同步交付目录 + 补丁说明追加记录。
